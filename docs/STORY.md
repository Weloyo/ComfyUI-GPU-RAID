# Сюжет → видео: История / Раскадровка / Видеоряд

Пишете сюжет — LLM (или эвристика) разбивает его на сегменты с таймингом,
воркеры параллельно рендерят ключевые кадры и FLF2V-сегменты, результат
склеивается в одно видео. Три ноды на канве, каждая отвечает за свой шаг:

```
История ──LLM──► план (сегменты с таймингом + камера, style_bible)
   │
   │ коннектор GPURAID_PROJECT
   ├────────────────► Раскадровка ──► кадры: T2I-шаблон, параллельно на всех GPU
   │                                   (кадр i — конец сегмента i-1 И начало
   │                                    сегмента i → непрерывность)
   └────────────────► Видеоряд ──► сегменты: FLF2V(кадр i, кадр i+1), параллельно
                                    ├─ Черновик (дешёвый предпросмотр)
                                    └─ Финал
                                    └─ склейка: concat / экспорт с тримами и кроссфейдом
```

Все три ноды работают с **одним и тем же проектом** (`output/gpuraid/<label>/manifest.json`)
— он переживает рестарты; перегенерация любого кадра/сегмента работает без
открытого канваса.

## Быстрый старт

1. Панель GPU RAID → Режимы → **«♾️ Бесконечное видео»** (MiniMax H3) —
   готовый пример: История+Раскадровка+Видеоряд уже связаны коннектором,
   сегмент-шаблон H3 подключён к Видеоряду. Или соберите свой:
   - **Видеоряд**: на канве — FLF2V-workflow с двумя `LoadImage`
     (заголовки **GPURAID:START_IMAGE**/**GPURAID:END_IMAGE** — Раскадровка
     сама подставит в них ключевые кадры), нода с промптом сегмента
     (заголовок **GPURAID:PROMPT**), Save-нода видео (найдётся сама, или
     пометьте **GPURAID:VIDEO_OUT**); опционально нода с числовым виджетом
     `steps`, помеченная **GPURAID:STEPS** — тогда «Черновик ▶» сможет
     занижать число шагов сэмплера, не только разрешение. Кнопка «Шаблон
     сегмента из канвы» в теле ноды сохраняет это в проект.
   - **Раскадровка**: T2I-workflow с нодой промпта (**GPURAID:PROMPT**) и
     Save-нодой кадра (найдётся сама, или **GPURAID:KEYFRAME_OUT**). Кнопка
     «Шаблон кадра из канвы». Без него — встроенный дефолт (Z-Image).
   - Соедините выход **project** Истории со входом **project** обеих нод
     (или просто заполните дропдаун «проект:» в их теле вручную — коннектор
     необязателен, только удобство).
2. Заполните **Историю** — сюжет, потолки длительности (на сегмент и на весь
   ролик — LLM решает фактическую длительность каждого сегмента сам, в этих
   пределах), при желании модель/системный промпт/температуру. Нажмите
   **«План ▶»** (или Queue, пока включён `on_queue`).
3. В **Раскадровке** — дропдаун «проект:» (или коннектор уже подхватил) →
   **«Кадры ▶»**. Проверьте кадры, при необходимости правьте промпт и жмите
   «заново» в теле ноды.
4. В **Видеоряде** — захватите шаблон сегмента (если не пример), затем
   **«Черновик ▶»** для быстрой проверки монтажа целиком, потом
   **«Финал ▶»** для чистового рендера. **«Экспорт»** внизу тела ноды
   собирает итоговое видео.

## LLM — характер сценариста

`base_url`/ключ — глобальное подключение (панель → «Подключения и ключи» →
LLM, один эндпоинт на всех сюжетов: Ollama, LM Studio, OpenRouter…). Модель,
системный промпт, температура, лимит токенов — виджеты **самой ноды
Истории**: это «характер» конкретного сценариста, можно держать несколько
нод Истории с разными характерами (жанр, стиль подачи) под разные сюжеты —
не глобальная настройка на всё расширение.

Без LLM (галка `use_llm` или недоступный endpoint) сюжет режется эвристикой
по предложениям/абзацам — план тот же, просто промпты стоит причесать
руками; `style_bible` в этом случае пустой.

## Тайминг сегментов — решает сценарист, в пределах потолков

LLM сам решает, сколько сегментов нужно и сколько длится каждый (поле
`segment_duration_s` — только ориентир). Пользователь задаёт два потолка на
ноде Истории:
- **`max_segment_duration_s`** — предел на ОДИН сегмент (по умолчанию 15с —
  столько MiniMax H3 физически считает за один вызов);
- **`max_total_duration_s`** — предел на весь ролик.

Если план вышел за потолки — сначала каждый сегмент клампится к своему
пределу, затем, если сумма всё ещё больше общего потолка, все сегменты
пропорционально сжимаются разом (не обрезаются с конца — так финал истории
не теряется молча).

## Непрерывность кадров — style_bible

LLM пишет не только сюжет по сегментам, но и **style_bible** — устойчивые
визуальные приметы всей истории (внешность персонажей, площадка, освещение,
эпоха/техника съёмки). Она дословно приклеивается к промпту КАЖДОГО кадра в
момент рендера (не при создании плана — можно поправить её в теле ноды
Истории и перерендерить кадры, не переписывая все промпты вручную). Это
единственный механизм непрерывности сейчас (`continuity_mode: style_only` на
Раскадровке) — более сильный (цепочка img2img от кадра к кадру) в планах.

## Формат промпта сегмента — официальный MiniMax H3

`prompt_format: minimax_h3` (по умолчанию на Видеоряде) строит промпт по
официальному гайду MiniMax
(`docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md`, MiniMaxAI/MiniMax-H3): один
сегмент — один `[Shot 1]`, обязательная фраза выравнивания первого/
последнего кадра по секундам («Picture 1 aligns with the 0.00-second mark;
Picture 2 aligns with the S.SS-second mark»), длительность двумя знаками
после запятой. LLM Истории также кладёт в промпт сегмента указание камеры
(тип движения/амплитуда/скорость) словарём из того же гайда — роль
«оператора», которую раньше совмещал один Сценарист, теперь явная часть
того, что пишет История.

`prompt_format: raw` — промпт сегмента (плюс style_bible) как есть, без
обёртки; нужен, если сегмент-шаблон — не MiniMax H3, а другая i2v/FLF2V-модель.

## Шаблон ключевых кадров

По умолчанию — встроенный Z-Image-шаблон (реальная локальная цель проекта).
Свой: соберите T2I-workflow на канве (нода промпта — **GPURAID:PROMPT**,
выход — единственный SaveImage или маркер **GPURAID:KEYFRAME_OUT**) и
нажмите «Шаблон кадра из канвы» в теле Раскадровки.

Кадры рендерятся строго в разрешении канвы сегментов: H3 компонует первый
кадр растяжением, а последний — кадрированием, и при другом аспекте стык
между сегментами был бы виден. Размер прописывается в `Empty*Latent*`-ноды
шаблона.

## Черновик / Финал

Видеоряд рендерит сегменты в двух вариантах: **Черновик** — дешёвый (по
умолчанию половина разрешения финала; `preview_short_edge`/`preview_steps`
на ноде — явный override, второй требует маркер **GPURAID:STEPS** в
шаблоне сегмента) — чтобы проверить монтаж всей истории целиком, не тратя
время на полное качество каждого сегмента. **Финал** — по умолчанию.
Оба варианта хранятся отдельно (`segments[i].preview` и `segments[i]`),
черновик не трогает статус готовности проекта — можно гонять его сколько
угодно раз, не мешая финальному рендеру.

## Правки после рендера

- промпт/сид сегмента → «Сохранить» (без рендера) или «заново» (перерендер,
  тем же форматом — MiniMax/raw и style_bible, что и массовый рендер);
- промпт/сид кадра → «заново»: смежные готовые сегменты помечаются
  «кадр изменён» — перерендерите их «Финал ▶» (берёт только неготовые и
  устаревшие);
- порядок/исключение/тримы/кроссфейд персистятся в манифест;
- «Экспорт» пересобирает финальное видео с учётом правок.

Редактор — тот же, что у «Длинное видео» ([LONGVIDEO.md](LONGVIDEO.md)),
просто каждая из трёх нод показывает свою часть одного проекта.
