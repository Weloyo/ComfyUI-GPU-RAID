# Pipeline: одна большая модель по частям на нескольких GPU

Режим для моделей, которые не влезают в один GPU: компоненты пайплайна
(текст-энкодер, диффузия, VAE-декод) разъезжаются по разным машинам,
промежуточные тензоры (CONDITIONING/LATENT/IMAGE/AUDIO) едут между ними
файлами-«бандлами». Спец-ноды в workflow не нужны — берётся обычный граф.

Это **конвейер по компонентам**, а не объединение VRAM: один шаг диффузии
по-прежнему считается на одной GPU. Зато 40 ГБ весов MiniMax H3 больше не
обязаны помещаться на одну карту: энкодер+семплинг могут жить на Colab A100,
а декод — локально.

## Как пользоваться

1. Откройте обычный workflow (пример: Режимы → **«🐘 Большая модель»**).
2. Бросьте на канву ноду **GPU RAID Конвейер (шардинг)** и нажмите в ней
   «Проанализировать». Расширение разрежет граф на «острова»:
   - рёбра типов MODEL/CLIP/VAE/GUIDER/… разрезать нельзя — их ноды остаются
     вместе;
   - лоадеры реплицируются: видео-VAE H3 нужен и энкоду (на большой GPU),
     и декоду (локально) — он будет загружен на обеих машинах;
   - разрез идёт только по LATENT/CONDITIONING/IMAGE/AUDIO/MASK.
3. Проверьте раскладку (оценка VRAM у каждой стадии, оценка трафика у каждого
   разреза; всё правится селекторами прямо в ноде) и жмите «Запустить конвейер ▶».
   Раскладка хранится в свойствах ноды и сохраняется вместе с workflow, так что
   при следующем открытии анализ можно не повторять — достаточно Queue
   (виджет `on_queue`) или кнопки запуска.
4. Прогресс стадий — панель → «Задания»; результат — `output/gpuraid/<label>_…/`.

## Что происходит под капотом

- Мастер собирает граф каждой стадии, вставляя `GPU RAID Save Bundle` на
  выходных разрезах и `GPU RAID Load Bundle` на входных.
- Стадии идут топологическими волнами; независимые (видео- и аудио-декод)
  выполняются параллельно.
- Бандл = safetensors (dtype сохраняется, H3 AV-NestedTensor поддержан);
  мастер скачивает его со стадии-источника и заливает стадии-потребителю —
  топология «звезда», воркерам не нужно видеть друг друга.
- Когда у воркера закончились стадии, ему шлётся `/free` — VRAM освобождается,
  не дожидаясь конца конвейера.

## Ограничения

- Разрез IMAGE **после** VAEDecode — это гигабайты (авторазмещение всегда
  прижимает декод+сохранение к локальной машине; не переселяйте их без нужды).
- cloudflared-туннель режет запросы ~100 МБ: анализатор предупреждает о
  разрезах крупнее лимита — держите такие пары стадий на одном воркере.
  Латент/кондишн H3 при 15-секундном видео — десятки МБ, проходит.
- Модели каждой стадии должны лежать на её воркере (пресет `minimax_h3` в
  ноутбуках скачивает все 4 файла; проверка — кнопка «Проверить» у воркера).
- 15 секунд — потолок самого H3 (сетка 17k+5, тренирован до ~362 кадров),
  Pipeline его не расширяет; для длинных видео берите «Сценариста».
