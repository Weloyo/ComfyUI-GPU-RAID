# Жизненный цикл воркеров: режимы, автостоп, автоподключение

Облачные GPU должны работать только пока идёт обработка — иначе горят квоты
и compute units. Расширение решает это тремя механизмами.

## 1. Режимы (нода «GPU RAID Воркеры» на канве)

| Режим | Поведение |
|---|---|
| ⚡ **Держать** | воркеры не останавливаются (серия запусков подряд) |
| 🌙 **Эко** (дефолт) | автостоп облачного воркера после N минут простоя (поле рядом; дефолт 10) |
| ⏻ **Сразу гасить** | остановка сразу после завершения задания (грейс 30 с) |
| 🏠 **Только локально** | облачные воркеры не получают заданий; уже поднятые — гасятся |

Дополнительно:
- **сценарий привязки** — в ноде-лоадере: у платформы (Colab/Kaggle) или
  конкретного воркера может быть свой режим (держать/эко/гасить сразу),
  перекрывающий глобальный; платформенный сценарий переживает перерождение
  сессии;
- 📌 у воркера — «закреплён»: автостоп его не трогает никогда;
- `budget_min` в настройках — жёсткий потолок длительности сессии (работает
  при любом режиме, кроме закреплённых);
- пока в системе есть активные задания, никто не останавливается (в т.ч. в
  паузах между сегментами chain-цепочки);
- «⏻» — остановить руками прямо сейчас: в ноде «Воркеры» или в ноде-лоадере
  привязанной модели.

Остановка = POST на воркера → watchdog в ноутбуке видит сигнал → гасит
ComfyUI и туннель → Colab: `runtime.unassign()` (рантайм освобождается),
Kaggle-batch: выход из скрипта (сессия завершена, квота не тратится).
Самостраховка `MAX_SESSION_MIN` в ноутбуке гасит рантайм, даже если мастер
умер.

## 2. Автоподключение (gist-rendezvous)

Туннель воркера каждый раз получает случайный адрес. Чтобы не копировать
строки руками:

Всё делается в панели → **«Подключения и ключи» → GitHub**:

1. Кнопка «Создать токен» открывает страницу GitHub с **уже проставленным**
   scope `gist` — остаётся нажать Generate и скопировать токен.
2. Вставьте токен в поле и нажмите «Сохранить и проверить» — расширение
   сходит в GitHub API и покажет, под каким аккаунтом токен работает.
3. Нажмите «Создать приватный gist» — мастер создаст его сам и пропишет
   `gist_id`. (Если gist уже есть — просто вставьте его id или ссылку.)
4. Токен добавьте в секреты платформы под именем **GH_TOKEN** (Colab: панель
   🔑; Kaggle: Add-ons → Secrets, включить для ноутбука). `GIST_ID` вводить
   не нужно — ноутбук находит rendezvous-gist сам по токену (по описанию
   гиста); в Colab туда же один раз добавьте `I_USE_PAID_COLAB = true` и,
   по желанию, `MODEL_PRESET`.

Проверка запоминается на сервере: повторно расширение ничего не спрашивает.
Кнопка «Забыть» удаляет токен и gist_id.

Дальше всё само: воркер публикует свой адрес в gist (файл на сессию — воркеры
не затирают друг друга), мастер опрашивает gist каждые ~30 с и добавляет/
обновляет воркеров, при перерождении туннеля адрес обновляется автоматически.
Ручная вставка строк остаётся как запасной путь.

## 3. Автозапуск

- **Kaggle** — полностью автоматический: кнопка ▶ в ноде-лоадере с привязкой
  Kaggle (или «▶ Kaggle-воркер» в ноде «Воркеры»). Нужны kaggle.json и
  настроенный gist — и то и
  другое настраивается в разделе «Подключения и ключи» (там же кнопка
  «Установить kaggle CLI», если пакета нет). Мастер пушит приватный
  batch-кернел через официальный kaggle CLI; кернел сам ставит всё,
  публикует адрес и завершает сессию по команде остановки.
  В Kaggle Secrets должен лежать GH_TOKEN (и HF_TOKEN при необходимости).
- **Colab** — у Colab нет API запуска рантаймов; кнопка «Открыть
  Colab-ноутбук» открывает ноутбук, дальше руками только Runtime → Run all.
  Всё остальное (регистрация, автостоп) — автоматическое.

## Отладка

`GET /gpuraid/lifecycle` — что тикер думает о каждом воркере (простой, возраст
сессии, решение и причина) и статус rendezvous. Статусы воркеров: зелёный —
online, синий — остановлен нами, красный — недоступен.
