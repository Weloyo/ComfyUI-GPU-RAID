# Google Colab: воркер на L4/A100 (только платный тариф)

## ⚠️ Про правила

FAQ Google Colab на **бесплатном** тарифе прямо запрещает
«running distributed computing workers» и «remote control such as SSH shells» —
ровно то, чем является воркер. На **платных** тарифах (Pro, Pro+, Pay-As-You-Go
— при положительном балансе compute units) эти ограничения сняты.

Поэтому ноутбук `notebooks/colab_worker.ipynb` требует явно подтвердить
платный тариф и не работает без этого. Подтверждение делается ОДИН раз —
секретом `I_USE_PAID_COLAB = true` в Colab Secrets (или разово строкой
`I_USE_PAID_COLAB = True` в ячейке). Не запускайте его на бесплатном тарифе:
рискуете аккаунтом Google.

## Что даёт Colab Pro (~$10/мес, 100 CU)

- **L4 24 ГБ** (~1.9 CU/час) — лучший вариант: тянет Flux, Wan 2.2 fp8-видео,
  bf16 работает (никаких `--force-fp16`).
- A100 40 ГБ — для самых тяжёлых задач, но дорог по CU.
- Сессии до 24 ч; при нулевом балансе CU действуют ограничения бесплатного
  тарифа — следите за балансом.

## Настройка ОДИН раз на аккаунт

Ноутбук каждый раз открывается из GitHub заново — правки ячеек не
сохраняются, поэтому конфиг он читает из **Colab Secrets** (🔑 слева;
секреты живут в аккаунте Google и переживают любые рантаймы):

| Секрет | Значение |
|---|---|
| `GH_TOKEN` | GitHub-токен с правом на Gists (тот же, что в панели мастера) |
| `I_USE_PAID_COLAB` | `true` — подтверждение платного тарифа |
| `MODEL_PRESET` | опционально: `minimax_h3` / `sdxl` |
| `HF_TOKEN` | опционально: gated-модели HF |

`GIST_ID` вводить не нужно: ноутбук сам находит rendezvous-gist по
`GH_TOKEN` (по описанию, которое пишет мастер при создании гиста). До этого
один раз настройте GitHub на мастере: панель → «Подключения и ключи» →
GitHub (токен + кнопка «Создать приватный gist») —
см. [docs/LIFECYCLE.md](LIFECYCLE.md).

## Запуск (каждый раз)

1. Кнопка **▶** у Colab-привязки в лоадере (или в ноде «Воркеры») — откроется
   ноутбук. API запуска у Colab нет, поэтому дальше руками:
2. Runtime → Change runtime type → **A100/L4**, затем **Runtime → Run all**.
   При первом запуске Colab спросит доступ ноутбука к секретам — разрешите.
3. Всё: воркер публикует адрес в gist, мастер подхватывает его за ~30 секунд,
   он появляется в списках воркеров у лоадеров. Без настроенного gist в конце
   печатается строка `gpuraid://…` — вставьте её в ноду «GPU RAID Воркеры».

`USE_DRIVE_CACHE = True` (дефолт) — кэш моделей в
`MyDrive/gpuraid_models/<папка>/`: скачанные модели переживают перезапуски
(Drive медленнее локального диска, но быстрее повторного скачивания).

## MiniMax H3 (видео, ~40 ГБ весов)

Секрет `MODEL_PRESET = minimax_h3` работает так же, как в Kaggle-ноутбуке —
качает 4 файла напрямую с HF в HF-кэш. Ноутбук сам добавляет `--cache-none`. Для GPU
с большим VRAM (A100/96 ГБ и т.п.) системная RAM всё равно может быть тесной —
если тариф даёт High-RAM (Runtime → Change runtime type), включите его.

**Важно: включите `USE_DRIVE_CACHE = True`.** Без него каждый новый рантайм
(эфемерный диск) заново качает все ~40 ГБ с HF. С `USE_DRIVE_CACHE = True`
готовые файлы копируются в `MyDrive/gpuraid_hf_cache/<папка>/` (плоские копии,
не symlink) — первая сессия качает как обычно и сохраняет копию, все
следующие копируют оттуда вместо повторного скачивания. Нужно ~40+ ГБ
свободного места в Google Drive.

Копии, а не symlink на HF-кэш внутри Drive — принципиально: Drive
FUSE-mount ненадёжен для вложенных symlink-цепочек, которые использует кэш
`huggingface_hub` (snapshot → blob). На практике это приводило к тому, что
крупные файлы (5–20 ГБ) выглядели скачанными (100% в прогресс-баре), но при
реальном использовании ComfyUI падал с `FileNotFoundError` — `os.path.lexists`
был `True`, `os.path.exists` (по цепочке) — `False`. Локальный HF-кэш всегда
остаётся на быстром локальном диске сессии; Drive используется только как
плоское хранилище готовых копий между сессиями.

## Типичный сценарий с вашим парком

- Kaggle 2×T4 — страйпинг SDXL/Z-Image картинок;
- Colab L4 — offload видео Wan 2.2 fp8 или Flux-генерация;
- локальная 4070 Ti — всё вместе с ними через work-stealing.
