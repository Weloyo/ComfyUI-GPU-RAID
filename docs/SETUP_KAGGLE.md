# Kaggle: два бесплатных T4-воркера с одной сессии

## Что даёт Kaggle

- **GPU T4 x2** — две Tesla T4 по 16 ГБ ⇒ ноутбук поднимает **два** инстанса
  ComfyUI (`CUDA_VISIBLE_DEVICES=0/1`, порты 8188/8189) и **два** туннеля =
  два воркера в вашем RAID.
- ~**30 ч GPU в неделю** (квота видна в профиле), сессия до **12 ч**.
- Правила Kaggle не запрещают такую схему (в отличие от бесплатного Colab).

## Разовая подготовка

1. Аккаунт Kaggle + **верификация телефона** (иначе GPU и интернет недоступны).
2. Опубликуйте репозиторий расширения на GitHub и пропишите `REPO_URL`
   в ноутбуке (или приложите исходники датасетом — см. ниже).
3. **Соберите Datasets с моделями** — ключ к быстрому старту: запустите
   `notebooks/kaggle_dataset_prep.ipynb`, он скачает модели с HF в
   `/kaggle/working/gpuraid_dataset` и подскажет, как сохранить это как
   приватный Dataset. Датасеты монтируются в `/kaggle/input` мгновенно —
   воркер готов за ~3 минуты вместо 15–20.
   - `gpuraid-sdxl` — SDXL-чекпоинт для страйпинга картинок (~7 ГБ);
   - `gpuraid-wan-gguf` — Wan 2.2 i2v **GGUF Q4** + UMT5 GGUF + VAE для
     offload-видео (fp8-версии 14B в 16 ГБ T4 не влезают — только GGUF);
   - секрет `HF_TOKEN` добавьте в Add-ons → Secrets, если модель гейтится.

## Запуск воркера

### Полностью автоматически (рекомендуется)

Один раз настройте автоподключение и автозапуск ([docs/LIFECYCLE.md](LIFECYCLE.md)):

Всё, кроме шага 3, делается в панели → **«Подключения и ключи»**: там ссылки
на нужные страницы, поля для вставки и проверка ключа одной кнопкой.

1. **GitHub**: «Создать токен» (scope `gist` уже проставлен) → вставить →
   «Сохранить и проверить» → «Создать приватный gist» (id пропишется сам).
2. **Kaggle**: «Скачать kaggle.json» → вставить содержимое файла в поле →
   «Сохранить и проверить». Если нет пакета — кнопка «Установить kaggle CLI»
   (это `pip install kaggle` в питон мастера).
3. В Kaggle: Add-ons → Secrets → добавьте **GH_TOKEN** (тот же токен) и, при
   необходимости, HF_TOKEN; включите их для ваших ноутбуков.

Дальше: панель → «Добавить воркеров» → **«Запустить Kaggle-воркера»** — мастер
пушит приватный batch-кернел, тот сам всё ставит, публикует адрес в gist и
появляется в панели. Режимы Эко/«Сразу гасить» завершают сессию автоматически
(квота не тратится на простой).

### Вручную (интерактивный ноутбук)

1. Создайте ноутбук из `notebooks/kaggle_worker.ipynb` (File → Import Notebook).
2. Справа: Accelerator = **GPU T4 x2**, Internet = **On**, Add Input → ваши
   датасеты с моделями.
3. При настроенном gist пропишите `GIST_ID` в конфиге — воркеры добавятся
   сами; иначе в конце будут напечатаны **две строки** `gpuraid://…` —
   вставьте обе в панель GPU RAID.
4. Оставьте вкладку открытой (ячейка watchdog держит сессию, перезапускает
   умерший туннель и завершает рантайм по команде мастера).

## Куда на Kaggle ложатся модели

`/kaggle/working` (там же ComfyUI воркера) ограничен **20 ГБ** — один набор
весов его переполняет. Поэтому обе дороги к моделям ведут мимо него:

- `MODEL_PRESET` качает в HF-кэш на эфемерном диске и симлинкует в `models/`;
- **рассылка из панели** («Модели: ссылки для воркеров») льёт файл в
  `/kaggle/tmp/gpuraid_models/<папка>/` и тоже оставляет симлинк — каталог
  задаёт bootstrap переменной `GPURAID_MODELS_DIR`.

Свободное место проверяется **до** закачки: если не хватает, воркер отвечает
понятной ошибкой, а не падает на последнем гигабайте.

## MiniMax H3 (видео, ~40 ГБ весов)

Не нужен отдельный Dataset — `MODEL_PRESET = "minimax_h3"` качает все 4 файла
напрямую с HF (`Comfy-Org/MiniMax-H3`, не гейтится) в HF-кэш. Ноутбук сам переключает `DUAL_T4 = False`
(один инстанс на одной T4 — 40 ГБ весов при 32 ГБ RAM сессии не тянут два) и
добавляет `--cache-none`. Первый запуск (скачивание + прогрев) может занять
дольше обычного — если воркер в панели GPU RAID виснет на первом видео-джобе,
поднимите `settings.timeouts.video_startup_s` в `workers.json` (например, до
1200с).

## Особенности T4

- T4 **не поддерживает bf16** — ноутбук запускает ComfyUI с `--force-fp16`.
  Используйте fp16/fp8-совместимые модели: SDXL, Z-Image Turbo, GGUF-кванты.
  Flux на T4 не рекомендуется (медленно/тесно) — для него Colab L4.
- Имена моделей на воркере почти наверняка отличаются от ваших локальных
  (например, у вас `sdxlCustomMerge_v7.safetensors`, на воркере
  `sd_xl_base_1.0.safetensors`). Нажмите **Проверить** у воркера в панели —
  жёлтый чип покажет отличия, кнопка `→ имя` запишет remap в один клик.

## Обрывы

- Туннель cloudflare живёт, пока жива сессия; URL меняется при каждом
  перезапуске. Умер туннель → перезапустите ячейку установки (идемпотентна) →
  в панели кнопка **URL** у воркера → вставьте новый адрес.
- Умерла сессия посреди job — юниты автоматически доедут на оставшихся GPU.
- Fallback-туннель, если cloudflared не выдал URL:
  `!ssh -o StrictHostKeyChecking=no -p 80 -R0:localhost:8188 a.pinggy.io`
  (бесплатный pinggy меняет URL каждые 60 минут). Ещё вариант — zrok (нужен
  аккаунт, зато стабильный URL).
