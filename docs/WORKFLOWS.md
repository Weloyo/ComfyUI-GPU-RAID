# Workflow-ы для GPU RAID: правила и пресеты

## Страйпинг (Distributor + Collector)

Минимальная схема — [example_workflows/stripe_sdxl.json](../example_workflows/stripe_sdxl.json):

1. `GPURAID Distributor` → выход **seed** в **KSampler.seed**
   (ПКМ по KSampler → *Convert widget to input* → seed, если вход не виден).
2. `GPURAID Collector` — сразу после `VAEDecode`, его выход — в Save/Preview
   и любую последующую обработку.
3. Всё, что **до** Collector, исполняется на каждом воркере (свой сид);
   всё, что **после**, — один раз на мастере над собранным батчем.

### Семантика сидов

Вариант *i* получает `seed = base_seed + i`. Это **не то же самое**, что
`batch_size=N` на одной машине (там батч тянет шум из одного генератора
последовательно). Зато результат воспроизводим при любом составе воркеров:
хотите повторить вариант 5 — выставьте сид `base+5` в обычном запуске.
`batch_size` при этом можно оставлять >1: суммарно получится
`total_variants × batch_size` изображений.

### Что нельзя класть в распределяемую ветку

- Ноды `GPURAID:*` (валидатор не пустит).
- Ноды, которых нет на воркере, — проверяйте кнопкой **Проверить** (parity).
- `LoadImage`/`VHS_LoadVideo` в ветке — можно: файлы зальются на воркера
  автоматически (лимит cloudflared ~100 МБ на файл).

## min_vram_gb: ориентиры

| Workflow | min_vram_gb | Комментарий |
|---|---|---|
| SD 1.5 | 4 | везде |
| SDXL / Pony | 8 | T4 ok |
| Z-Image Turbo | 8 | лучший speed/quality на T4 |
| Flux fp8 | 12–14 | T4 медленно; лучше L4 |
| Wan 2.2 14B GGUF Q4 | 10 | T4 ok (offload) |
| Wan 2.2 14B fp8 | 16+ | L4/A100, не T4 |

Воркеры с меньшим VRAM не получат юниты этого job (в панели будет причина).

## Модели на воркерах: имена и remap

Одинаковый **класс лоадера** обязателен, имя файла может отличаться — жёлтый
parity-чип предложит однокликовый remap (`ваше_имя → имя_на_воркере`,
хранится per-worker). Разные лоадеры (у вас `UNETLoader` fp8, на воркере GGUF
`UnetLoaderGGUF`) remap-ом не решаются — держите отдельный GGUF-вариант
workflow и запускайте его через Offload.

## Offload

Бросьте на канву ноду **GPU RAID Выполнить на воркере**, выберите воркера в
выпадашке и нажмите кнопку (или **Queue** — пока включён виджет `on_queue`).

Работает с **любым** workflow без изменений (ноды GPURAID, если есть,
аккуратно выкусываются). Требования: на воркере есть все custom-ноды и модели
графа; в графе есть Save-нода (иначе нечего забирать). Результаты падают в
`output/gpuraid/<label>_<время>/`.

## Tiled Upscale

`LoadImage → GPURAID Tiled Upscale → SaveImage`
([пример](../example_workflows/tiled_upscale.json)). Модель-апскейлер должна быть
на воркерах (или скачайте её кнопкой из панели — она маленькая). `tile` 768 и
`overlap` 64 — разумный дефолт; при видимых швах увеличьте overlap.
